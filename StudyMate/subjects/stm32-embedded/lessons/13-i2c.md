## 这一课要解决的问题

::: goal
读完你能：说清 I2C 为什么必须用开漏加外部上拉；看懂起始、应答、停止三个关键时序；自己拼出"设备地址 + 寄存器地址 + 数据"的写序列；用 I2C 驱动一块 0.96 寸 OLED 显示数字；知道软件 I2C 和硬件 I2C 什么时候各用哪个。
:::

串口是"一根线对一个设备"。现实里更常见的是**一根线挂好几个芯片**——一个温湿度传感器、一个 OLED、一个 EEPROM，全接在同样的两根线上。这就是 I2C。

它只有两根线：

- **SCL**：时钟线，由主机产生
- **SDA**：数据线，双向

## 1. 为什么必须是开漏：回到 s3 的"两个开关"

s3 讲过：开漏输出的引脚内部**只有下面那个开关**（接 GND 的 N-MOS），上面没有开关，只能"拉低"或"放手"（高阻）。

I2C 把这条规则用到了极致：**总线上所有设备的 SDA、SCL 都是开漏，外面各接一个上拉电阻到 3.3V**。

于是线上电平是"线与"的结果：

| 设备 A | 设备 B | 线上电平 |
| --- | --- | --- |
| 放手 | 放手 | 上拉电阻拉高 → **1** |
| 拉低 | 放手 | 被 A 拉低 → **0** |
| 放手 | 拉低 | 被 B 拉低 → **0** |
| 拉低 | 拉低 | **0** |

::: note 如果改成推挽会怎样（这是面试原题）
推挽输出上面也有开关，会主动输出高电平（接 3.3V）。

假设 A 想输出 1（把线接 3.3V），B 想输出 0（把线接 GND）——**3.3V 和 GND 之间通过两个导通的 MOS 管直接短路**。电流只受 MOS 管导通电阻限制，几个安培，芯片当场烧掉。

开漏的好处正是：**没人会主动输出高电平，所以永远不会"一个送 3.3V、一个送 GND"**。大家只会"拉低"或"不管"，冲突时最坏结果就是都拉低（还是 0），安全。

这就是 I2C 必须开漏、必须外部上拉的根本原因。上拉电阻不是"可选优化"，是**电路能工作的前提**。
:::

::: warn 忘接上拉电阻的现象
模块上通常自带 4.7kΩ 上拉（OLED 模块背面一般有），所以很多人没意识到它的存在。但如果自己画板、或者买的是裸芯片：

- **完全没上拉**：SDA/SCL 永远是低或浮空，主机发不出起始信号。现象是 `HAL_I2C_Master_Transmit` 一直返回 `HAL_ERROR` 或 `HAL_TIMEOUT`，逻辑分析仪上看不到任何波形跳变。
- **上拉太大（100kΩ）**：上升沿变缓，100kHz 下勉强能通，400kHz 下直接失败。示波器上看上升沿是个"斜坡"而不是"台阶"。
- **上拉太小（1kΩ）**：电流大、低电平抬不起来（低于 0.4V 的 Vil 要求），也通不了。

**标准值：100kHz 用 4.7kΩ，400kHz 用 2.2kΩ，短线可以用 10kΩ。**
:::

## 2. 三个必须认得的时序

I2C 没有片选线，靠**起始和停止信号**划分每一次通信。

| 信号 | SCL | SDA | 含义 |
| --- | --- | --- | --- |
| **起始 S** | 高 | **由高变低** | 总线忙，一次通信开始 |
| **停止 P** | 高 | **由低变高** | 总线空闲 |
| **数据位** | 高电平期间采样 | 只能在 SCL 低电平期间变化 | 保证采样时数据稳定 |
| **应答 ACK** | 第 9 个时钟 | 接收方把 SDA **拉低** | "收到了" |
| **非应答 NACK** | 第 9 个时钟 | 接收方放手（SDA 高） | "没有了/不要了" |

::: note 数据为什么只能在 SCL 低电平期间变
因为**起始和停止是靠"SDA 在 SCL 高电平期间跳变"定义的**。

如果数据位也能在 SCL 高电平期间随便跳，硬件就分不清"这是数据"还是"这是起始/停止"。规定"高电平期间 SDA 必须稳定"，起始和停止才有唯一的识别特征。

所以时序图里你永远看到：SCL 低 → SDA 变化 → SCL 变高（采样）→ SCL 变低 → 再变化。
:::

## 3. 地址：7 位地址 + 1 位读写

I2C 的从机地址是 **7 位**。第一帧发的是"地址左移一位，最低位放读写方向"：

$$\text{发送字节} = (\text{addr} \ll 1) \,|\, R/W$$

- `R/W = 0` → 主机要**写**
- `R/W = 1` → 主机要**读**

0.96 寸 OLED 常用 SSD1306 芯片，7 位地址是 **0x3C**（有的模块是 0x3D，由模块上的电阻决定）：

| 操作 | 计算 | 发送字节 |
| --- | --- | --- |
| 写 | `0x3C << 1 \| 0` | **0x78** |
| 读 | `0x3C << 1 \| 1` | **0x79** |

::: warn 90% 的"I2C 无应答"都是这一件事
网上代码里经常直接写 `0x78`，也经常写 `0x3C`，新手照抄就错。先把规矩说清楚：

- **数据手册、CubeMX 的从机地址栏**用的是 **7 位地址 0x3C**。
- **HAL 库所有 I2C 函数的 `DevAddress` 参数要的是"已经左移一位的 8 位地址"**，也就是 `0x3C << 1 = 0x78`。HAL 内部不会再帮你移位，它直接把这个字节写到 DR 上。

所以在头文件里把 7 位和 8 位都定义成宏，调用处只用宏名，就不会混：

**文件：`Hardware/Inc/ssd1306.h`**
```c
#ifndef __SSD1306_H
#define __SSD1306_H

#ifdef __cplusplus
extern "C" {
#endif

#include "main.h"

/* SSD1306 数据手册的 7 位地址是 0x3C；有的模块焊成 0x3D */
#define SSD1306_ADDR7       0x3CU
/* HAL 的 DevAddress 要"已左移一位"的 8 位值：写 0x78、读 0x79 */
#define SSD1306_ADDR8       (SSD1306_ADDR7 << 1)

#define SSD1306_CMD         0x00U   /* 控制字节：0x00 后面是命令 */
#define SSD1306_DATA        0x40U   /* 控制字节：0x40 后面是显存数据 */

#define SSD1306_PAGES       8U      /* 128×64：8 页 */
#define SSD1306_WIDTH       128U    /* 每页 128 列 */
#define SSD1306_I2C_TIMEOUT 100U    /* 100kHz 下 2 字节约 0.2ms，100ms 足够 */

void OLED_Init(void);
void OLED_Clear(void);
void OLED_SetPos(uint8_t page, uint8_t col);
void OLED_WriteCmd(uint8_t cmd);
void OLED_WriteData(const uint8_t *data, uint16_t len);
void OLED_Dot(uint8_t page, uint8_t col, uint8_t on);

#ifdef __cplusplus
}
#endif

#endif /* __SSD1306_H */
```

调用时写 `HAL_I2C_Master_Transmit(&hi2c1, SSD1306_ADDR8, buf, len, 100)` 就对；直接把 `0x3C` 传进去就是错，会 NACK。

看到 NACK 时，先检查这里是不是把 7 位地址直接传进去了，能省半小时。
:::

## 4. 一次写操作长什么样

以"给 OLED 写一个命令"为例：设备地址 0x3C、控制字节 0x00（表示后面是命令）、命令 0xAE（关显示）。

```
S | 0x78 | ACK | 0x00 | ACK | 0xAE | ACK | P
```

对应 HAL。驱动放 `Hardware/Src/ssd1306.c`，寄存器型从机的读写示例单独放一个文件：

**文件：`Hardware/Src/ssd1306.c`**
```c
#include "ssd1306.h"
#include "i2c.h"          /* hi2c1 在这里 extern 声明 */
#include <string.h>

/* 上电初始化序列，全部来自 SSD1306 数据手册（Application Note 表格） */
static const uint8_t s_init_cmds[] = {
    0xAE,        /* 关显示 */
    0xD5, 0x80,  /* 时钟分频 = 1，振荡频率档位 8 */
    0xA8, 0x3F,  /* 复用率 = 64 行（0x3F） */
    0xD3, 0x00,  /* 显示偏移 = 0 */
    0x40,        /* 显存起始行 = 0 */
    0x8D, 0x14,  /* 开电荷泵（必须，否则屏不亮） */
    0x20, 0x00,  /* 水平寻址模式 */
    0xA1,        /* 段重映射：列 127 → SEG0（左右不镜像） */
    0xC8,        /* COM 反向扫描：上下不镜像 */
    0xDA, 0x12,  /* COM 引脚配置：128×64 用 0x12 */
    0x81, 0xCF,  /* 对比度 0xCF */
    0xD9, 0xF1,  /* 预充电周期 */
    0xDB, 0x40,  /* VCOMH 电压 */
    0xA4,        /* 显示跟随显存 */
    0xA6,        /* 正常显示（非反白） */
    0x2E,        /* 关滚动 */
    0xAF         /* 开显示 */
};

/* 发一条命令：0x00 是 SSD1306 的控制字节，声明后面是命令流 */
void OLED_WriteCmd(uint8_t cmd)
{
    uint8_t buf[2] = {SSD1306_CMD, cmd};
    HAL_I2C_Master_Transmit(&hi2c1, SSD1306_ADDR8, buf, 2, SSD1306_I2C_TIMEOUT);
}

/* 连续写显存数据：一个事务最多 32 字节，避免栈上开大数组 */
void OLED_WriteData(const uint8_t *data, uint16_t len)
{
    uint8_t buf[33];                    /* 1 个控制字节 + 最多 32 字节数据 */
    while (len > 0U) {
        uint16_t n = (len > 32U) ? 32U : len;
        buf[0] = SSD1306_DATA;
        memcpy(&buf[1], data, n);
        HAL_I2C_Master_Transmit(&hi2c1, SSD1306_ADDR8, buf, (uint16_t)(n + 1U),
                                SSD1306_I2C_TIMEOUT);
        data += n;
        len  -= n;
    }
}

/* 定位到第 page 页（0~7）的第 col 列（0~127） */
void OLED_SetPos(uint8_t page, uint8_t col)
{
    uint8_t cmd[4];
    cmd[0] = SSD1306_CMD;
    cmd[1] = (uint8_t)(0xB0U | (page & 0x07U));   /* 页地址命令 0xB0~0xB7 */
    cmd[2] = (uint8_t)(col & 0x0FU);              /* 列地址低 4 位 */
    cmd[3] = (uint8_t)(0x10U | (col >> 4));       /* 列地址高 4 位 */
    HAL_I2C_Master_Transmit(&hi2c1, SSD1306_ADDR8, cmd, 4, SSD1306_I2C_TIMEOUT);
}

/* 清屏：8 页 × 128 列全部写 0 */
void OLED_Clear(void)
{
    static const uint8_t zeros[SSD1306_WIDTH] = {0};
    for (uint8_t p = 0; p < SSD1306_PAGES; p++) {
        OLED_SetPos(p, 0);
        OLED_WriteData(zeros, SSD1306_WIDTH);
    }
}

/* 点亮/熄灭某页某列最上面的像素（bit0 在上） */
void OLED_Dot(uint8_t page, uint8_t col, uint8_t on)
{
    uint8_t v = on ? 0x01U : 0x00U;
    OLED_SetPos(page, col);
    OLED_WriteData(&v, 1);
}

void OLED_Init(void)
{
    for (uint16_t i = 0; i < sizeof(s_init_cmds); i++) {
        OLED_WriteCmd(s_init_cmds[i]);
    }
    OLED_Clear();
}
```

**文件：`Hardware/Src/i2c_mem_demo.c`**（教学示例：寄存器型从机如 MPU6050 的读写，可删）
```c
#include "i2c.h"
#include <stdint.h>

#define MPU_ADDR (0x68 << 1)   /* MPU6050 的 7 位地址 0x68，左移一位给 HAL */

void I2C_MemDemo(void)
{
    uint8_t cmd = 0xAE;
    uint8_t id  = 0;

    /* 句柄、8 位地址、寄存器地址、地址宽度、数据、长度、超时 */
    HAL_I2C_Mem_Write(&hi2c1, MPU_ADDR, 0x00, I2C_MEMADD_SIZE_8BIT, &cmd, 1, 100);
    HAL_I2C_Mem_Read (&hi2c1, MPU_ADDR, 0x75, I2C_MEMADD_SIZE_8BIT, &id,  1, 100);
}
```

::: note 为什么是这几句
- `0x00` 控制字节不能省：SSD1306 靠它区分"接下来是命令还是显存数据"，少写这个字节，芯片会把命令 0xAE 当成显存数据画到屏上，现象是**屏幕某个角落多出一排点、命令完全没生效**。
- 超时参数写 `100`：100kHz 下 2 个字节连 ACK 约 0.2ms，100ms 余量足够；写成 `HAL_MAX_DELAY` 时，从机没接好程序会**永远卡在这一行**，看不出是哪里出错。
- 返回值要接：`HAL_I2C_Master_Transmit` 返回 `HAL_ERROR` 多半是 NACK、`HAL_TIMEOUT` 多半是总线被拉死。丢掉返回值，现象就是"代码跑得好好的，屏就是不亮"。
- 读寄存器必须用 `HAL_I2C_Mem_Read` 而不是 `Master_Receive`：单独 `Receive` 没法先告诉从机"我要哪个寄存器"，只能从上次的指针位置瞎读。`Mem_Read` 内部做了"写寄存器地址 → 重复起始 → 读"。
:::

::: note 为什么不用"自己拼数组 + Master_Transmit"做读操作
写寄存器其实可以拼 `{寄存器, 数据}` 一次发出去；但读操作中间必须插入一次**重复起始**（S 而不是 P），手拼做不到——要么先 `Transmit` 再 `Receive`（中间 HAL 会插入停止信号，从机把地址指针清掉，读回 0xFF），要么就得自己写时序。`Mem_Write`/`Mem_Read` 就是为了这两步而存在的封装，**能用封装就别手拼**。
:::

::: note 哪些代码"故意没写"
本文不写 `MX_I2C1_Init()` 和 `HAL_I2C_MspInit()`：前者配时钟频率和自身地址，后者在 `Core/Src/i2c.c` 里开 I2C1 时钟、把 PB6/PB7 配成"复用开漏"。**手写最容易漏的是 GPIO 模式写成推挽**，现象是第一个字节就 NACK（SDA 被主机强拉高，从机拉不低）。软件 I2C 没有这些，只有 GPIO 初始化（`MX_GPIO_Init()`），速度也只由 `delay_us` 决定，和 CubeMX 里填的 100k/400k 没有任何关系。
:::

::: note 读操作为什么要"先写后读"
I2C 读数据不是"直接说我要哪个寄存器"。流程是：

1. `S | 地址+W | ACK | 寄存器地址 | ACK` —— 先把要读的寄存器地址告诉从机（相当于"移动文件指针"）。
2. **`S`（重复起始）`| 地址+R | ACK | 数据 | NACK | P`** —— 再以读模式重新开始，从机把该寄存器的值吐出来。

HAL 的 `HAL_I2C_Mem_Read` 内部自动做这两步（用重复起始，不是停止再起始，避免总线被别的设备抢走）。这也是为什么它比 `Master_Receive` 更好用。
:::

## 5. OLED：I2C 上最常见的负载

0.96 寸 OLED 模块的核心是 **SSD1306** 驱动芯片：

- 分辨率 **128×64**
- 显存按"页"组织：8 页，每页 8 行像素，每列一个字节（纵向 8 个像素，低位在上）

所以显存是 `8 页 × 128 列 = 1024 字节`。

写显存的方式和写命令一样，只是控制字节不同：

| 控制字节 | 含义 |
| --- | --- |
| **0x00** | 后面全是**命令** |
| **0x40** | 后面全是**显存数据** |

定位、写一列、画点这三个函数已经在上面 `Hardware/Src/ssd1306.c` 的完整文件里（`OLED_SetPos` / `OLED_WriteData` / `OLED_Dot`）。要把像素拼成字符，还需要"字模 + 显示"这一层，单独放两个文件：

**文件：`Hardware/Inc/ssd1306_text.h`**
```c
#ifndef __SSD1306_TEXT_H
#define __SSD1306_TEXT_H

#ifdef __cplusplus
extern "C" {
#endif

#include "main.h"

#define OLED_FONT_W    5U   /* 字模宽 5 像素 */
#define OLED_FONT_H    7U   /* 字模高 7 像素（放在 8 像素高的页里） */
#define OLED_CHAR_W    6U   /* 每个字符占 6 列：5 列字模 + 1 列间隔 */

void OLED_ShowChar(uint8_t page, uint8_t col, char ch);
void OLED_ShowString(uint8_t page, uint8_t col, const char *str);
void OLED_ShowNum(uint8_t page, uint8_t col, uint32_t num, uint8_t len);

#ifdef __cplusplus
}
#endif

#endif /* __SSD1306_TEXT_H */
```

```c
{

    uint8_t idx;

    if (ch >= 'a' && ch <= 'z') ch = (char)(ch - 32);   /* 只做了一套大写 */
    if (ch < ' ' || ch > 'Z') ch = '?';
    idx = (uint8_t)(ch - ' ');

    buf[0] = SSD1306_DATA;
    memcpy(&buf[1], s_font5x7[idx], OLED_FONT_W);
    buf[OLED_CHAR_W] = 0x00;        /* 字符之间留 1 列空白 */
    OLED_SetPos(page, col);
    HAL_I2C_Master_Transmit(&hi2c1, SSD1306_ADDR8, buf, sizeof(buf), SSD1306_I2C_TIMEOUT);
}

void OLED_ShowString(uint8_t page, uint8_t col, const char *str)
{

        OLED_ShowChar(page, col, *str++);
        col = (uint8_t)(col + OLED_CHAR_W);
    }
}

void OLED_ShowNum(uint8_t page, uint8_t col, uint32_t num, uint8_t len)
{
    char tmp[11];
    if (len > 10U) len = 10U;
    for (uint8_t i = 0; i < len; i++) {
        tmp[len - 1U - i] = (char)('0' + num % 10U);   /* 从最低位往前填 */
        num /= 10U;
    }
    tmp[len] = '\0';
    OLED_ShowString(page, col, tmp);
}
```

::: note 为什么列地址要拆成两个字节
SSD1306 的"设置列"命令被拆成两条：低 4 位用 `0x00~0x0F`，高 4 位用 `0x10~0x1F`。所以 `col` 必须**按位拆开**，不能直接写 `col`。

老教程里常见一句 `uint8_t cmd[] = {0x00, 0xB0 | page, 0x00, 0x10};`——它把列地址写死成 0 了。现象很典型：**不管传什么 col，点永远画在最左边一列**。这就是"看起来能跑、实际参数没生效"的坑。
:::

::: note 为什么一条命令一条数据，不合并
可以把"定位 + 数据"拼成 `{0x00, 0xB0|page, 低4位, 0x10|高4位}` 再跟 `{0x40, dat}`，但中间必须换控制字节，一条 `Master_Transmit` 只能连续发同一种类型。想省时间就把整个页的 128 列拼成 `{0x40, d0…d127}` 一次发完——**这才是 OLED 库刷屏的做法**，一页一次 I2C 事务，比一个点两次快两个数量级。
:::

::: note 哪些代码"故意没写"
`0xB0`、`0x10`、`0x40` 这些命令字来自 SSD1306 数据手册，不是随便定的；初始化序列（关显示、设时钟、设复用率、开电荷泵…）在上面 `OLED_Init()` 的 `s_init_cmds[]` 里已经完整列出，顺序不能换——`0x8D,0x14`（开电荷泵）漏掉的现象就是"通信全对、屏全黑"。`hi2c1` 的初始化由 `MX_I2C1_Init()` 完成，不用手写。
:::

::: note 为什么写一个字节就画了 8 个点
SSD1306 的显存是**纵向排布**的：一个字节的 8 个 bit 对应同一列上连续的 8 行。

所以它不是"一个字节一个像素"，而是"一个字节管一列 8 个像素"。写汉字/数字时，字模按"列优先、低位在上"取模，正好一字节一列地推。

如果字模取模方式选成了"横向取模"，显示出来就是**旋转 90° 的乱码**——这是 OLED 调试第一大坑。
:::

::: warn 硬件 I2C 在 F103 上的历史包袱
STM32F103 的硬件 I2C 外设早年有已知的**总线死锁 / BUSY 卡死**问题（勘误手册里有记录），表现为：从机在传输中途掉电或复位，主机 I2C 状态机卡在 BUSY，之后所有通信都超时，只能整机复位。

所以**江协科技等主流教程在 F103 上都用软件 I2C**（GPIO 模拟 SCL/SDA 时序），牺牲一点速度换稳定。

选择建议：

- **学习、驱动 OLED/传感器**：软件 I2C，代码可控、能单步、不会卡死。
- **量产、高速（400kHz）、低 CPU 占用**：硬件 I2C + 超时检测 + 总线恢复（发 9 个时钟解锁）。
- **面试被问"软件 I2C 和硬件 I2C 区别"**：答"软件靠 GPIO 翻转、占 CPU、速度低但可移植可调试；硬件靠外设、不占 CPU、速度快但 F103 上有勘误、易死锁"。
:::

## 6. 软件 I2C 的核心就是四行

完整实现放两个文件（PB6 = SCL，PB7 = SDA），接口和时序分开：

**文件：`Hardware/Inc/i2c_bus.h`**
```c
#ifndef __I2C_BUS_H
#define __I2C_BUS_H

#ifdef __cplusplus
extern "C" {
#endif

#include "main.h"

/* CubeMX 里把 PB6/PB7 配成 GPIO_Output + Output Open Drain，并开内部上拉 */
#define I2C_SCL_PORT   GPIOB
#define I2C_SCL_PIN    GPIO_PIN_6
#define I2C_SDA_PORT   GPIOB
#define I2C_SDA_PIN    GPIO_PIN_7

void    I2C_Start(void);                        /* 起始：SCL 高时 SDA 下降 */
void    I2C_Stop(void);                         /* 停止：SCL 高时 SDA 上升 */

void    I2C_WriteBytes(uint8_t addr7, const uint8_t *data, uint16_t len);

}
#endif
```

**文件：`Hardware/Src/i2c_bus.c`**
```c
#include "i2c_bus.h"

#define SCL_H()    HAL_GPIO_WritePin(I2C_SCL_PORT, I2C_SCL_PIN, GPIO_PIN_SET)
#define SCL_L()    HAL_GPIO_WritePin(I2C_SCL_PORT, I2C_SCL_PIN, GPIO_PIN_RESET)
#define SDA_H()    HAL_GPIO_WritePin(I2C_SDA_PORT, I2C_SDA_PIN, GPIO_PIN_SET)
#define SDA_L()    HAL_GPIO_WritePin(I2C_SDA_PORT, I2C_SDA_PIN, GPIO_PIN_RESET)
#define SDA_READ() HAL_GPIO_ReadPin(I2C_SDA_PORT, I2C_SDA_PIN)   /* 开漏下读 IDR 即线上电平 */

/* 粗延时：72MHz 下内层循环约 3~4 个周期，18 次约 5μs，够 100kHz 用 */
static void delay_us(uint32_t us)
{
    while (us--) { for (volatile uint32_t i = 0; i < 18; i++) { } }
}

void I2C_Start(void)   /* SCL 高电平期间 SDA 下降 */
{
    SDA_H(); SCL_H(); delay_us(5);
    SDA_L(); delay_us(5);
    SCL_L();            /* 拉低 SCL，准备发第一位 */
}

void I2C_Stop(void)    /* SCL 高电平期间 SDA 上升 */
{
    SDA_L(); SCL_H(); delay_us(5);
    SDA_H(); delay_us(5);
}

uint8_t I2C_WaitAck(void)
{
    SDA_H();                    /* 开漏写 1 = 放手，线交给从机控制 */
    SCL_H(); delay_us(5);
    uint8_t ack = (uint8_t)SDA_READ();   /* 读到 0 → 从机拉低 → ACK */
    SCL_L(); delay_us(5);
    return ack;
}

void I2C_SendByte(uint8_t byte)
{
    for (uint8_t i = 0; i < 8U; i++) {
        if (byte & 0x80U) SDA_H(); else SDA_L();   /* MSB 先发 */
        byte <<= 1;
        SCL_H(); delay_us(5);                      /* 高电平期间数据稳定 */
        SCL_L(); delay_us(5);
    }
}

uint8_t I2C_ReadByte(uint8_t ack)
{
    uint8_t byte = 0;
    SDA_H();                                       /* 放手 = 输入态 */
    for (uint8_t i = 0; i < 8U; i++) {
        byte <<= 1;
        SCL_H(); delay_us(5);
        byte |= (SDA_READ() == GPIO_PIN_SET) ? 1U : 0U;
        SCL_L(); delay_us(5);
    }
    if (ack) SDA_L(); else SDA_H();                /* 主机回 ACK / NACK */
    SCL_H(); delay_us(5);
    SCL_L(); delay_us(5);
    return byte;
}

void I2C_WriteBytes(uint8_t addr7, const uint8_t *data, uint16_t len)
{
    I2C_Start();
    I2C_SendByte((uint8_t)(addr7 << 1));           /* 写方向：最低位 0 */
    I2C_WaitAck();
    for (uint16_t i = 0; i < len; i++) {
        I2C_SendByte(data[i]);
        I2C_WaitAck();
    }
    I2C_Stop();
}

uint8_t I2C_Probe(uint8_t addr7)
{
    I2C_Start();
    I2C_SendByte((uint8_t)(addr7 << 1));
    uint8_t ack = I2C_WaitAck();
    I2C_Stop();
    return ack;
}
```

引脚配置：**开漏输出 + 外部上拉**（或者用内部上拉，但内部上拉 40kΩ 偏弱，只能低速短距离）。

::: note 为什么没写"把 SDA 切成输入"
`SDA_READ()` 直接读就行。STM32 的引脚在**开漏输出**模式下，输入缓冲器依然是通的，`IDR` 反映的是引脚真实电平；输出 1 只是"放手"，不会和从机抢线。所以不需要 `GPIO_Init` 来回切方向——切方向反而会引入几个微秒的空窗，400kHz 下就是错位。

反过来，如果配成**推挽输出**，写 1 会把线强拉高，从机拉不低，ACK 永远读成 1，现象就是"程序以为每次都成功，其实从机根本没应答"。
:::

::: note 为什么延时是"大约"的
I2C 只规定最高频率（100k/400k），没有最低频率，慢一点不会错，所以不需要精确延时。`delay_us` 里的 18 次循环是按 72MHz 估的；`-O0` 和 `-O2` 编译出来差一倍也没关系——真正要提速到 400kHz，把 `delay_us(5)` 改成 `delay_us(1)` 并重新估算循环次数即可。

这就是软件 I2C 的取舍：**时序完全可控、能单步、能加超时解锁，但精度靠"猜"、CPU 全程等待**。硬件 I2C 反过来，配置一次就不用管，可 F103 上有 BUSY 死锁勘误（见上面的 warn）。
:::

::: note 哪些代码"故意没写"
没有 GPIO 初始化：PB6/PB7 的时钟、模式、速度都在 `MX_GPIO_Init()` 里由 CubeMX 生成，手写容易把开漏写成推挽。`I2C_WriteBytes` 只做"写一段"，没有做"读寄存器"（先写寄存器地址 → 重复起始 → 读），因为那需要多一层寄存器地址概念；本课把起始/停止/应答/收发字节这一层给全，其余照同样的节奏拼即可。
:::

::: warn 软件 I2C 的引脚方向问题
SDA 是双向的：发数据时是输出，收 ACK 时必须切成**输入**去读。

新手最常见的 bug：读 ACK 前忘了 `SDA_H()` 把线放开，引脚还拉着低，`SDA_READ()` 读到的永远是自己送出去的 0，于是"ACK 永远成功"——程序看着能跑，其实从机根本没应答。

正确做法：发完 8 位后，把 SDA 设为输入（或输出高电平"放手"），读第 9 个时钟的电平，读完再切回输出。
:::

## 7. 算一算

::: exercise 练习 1：地址与字节
某 EEPROM 的 7 位地址是 0x50。主机要往它的 0x0010 地址写 0xAB（16 位内部地址）。

1. 第一帧发的地址字节是多少（写）？
2. 整个写序列一共几个字节？
3. 100kHz 下，传输这几个字节最少要多久（不算起始/停止和 ACK 开销）？

::: answer
1. `0x50 << 1 | 0 = 0xA0`。
2. 序列是：`地址字节(0xA0) + 地址高字节(0x00) + 地址低字节(0x10) + 数据(0xAB)`，共 **4 个字节**。每个字节后还有一个 ACK 位。
3. 一个字节 8 位 + 1 个 ACK = 9 个时钟。100kHz 下一个时钟 10μs：

$$4 \times 9 \times 10\mu s = 360\mu s$$

实际还要加起始/停止各几个 μs，大约 **400μs**。所以 I2C 写 EEPROM 很慢，一次 1KB 要几百毫秒——这也是 EEPROM 写操作要"页写 + 等待 5ms"的原因。
:::
:::

::: exercise 练习 2：OLED 刷新要多久
128×64 的 OLED，全屏刷新一次要发 1024 字节显存。100kHz 的 I2C，理论最短时间是多少？400kHz 呢？

::: answer
每字节 9 个时钟（8 数据 + 1 ACK）。

100kHz：

$$1024 \times 9 / 100000 = 0.0922s \approx 92ms$$

400kHz：

$$1024 \times 9 / 400000 = 0.023s \approx 23ms$$

所以 **100kHz 下全屏刷新最多约 10 帧/秒**，做动画会明显卡顿；400kHz 约 40 帧/秒，勉强够用。

实用结论：OLED 做界面时**只刷新变化的区域**，不要每帧全屏推。这也是为什么很多 OLED 库有"局部刷新"接口。
:::
:::

## 8. 动手项目

::: project
**I2C 扫描器 + OLED 计数器**

1. 先写一个**总线扫描**：遍历 7 位地址 0x08~0x77，用 `HAL_I2C_IsDeviceReady()` 探测，把有应答的地址通过串口打印出来。
2. 用扫描到的地址初始化 OLED，显示：
   - 第一行：`STM32 I2C OK`
   - 第二行：一个每秒加 1 的计数
   - 第三行：当前 I2C 速度（100k / 400k）

**验收标准**：

1. 扫描能稳定找到 OLED 的地址（0x3C 或 0x3D），不重复、不遗漏。
2. OLED 上电后 1 秒内出字，**不花屏**（说明初始化命令序列完整）。
3. 计数每秒准确加 1，不跳变（说明没有在中断里刷新 OLED）。
4. 拔掉 OLED 再插上，程序不卡死（软件 I2C 应该能恢复；硬件 I2C 大概率卡 BUSY，正好对比）。

```c
    0xC8,        /* COM 反向扫描：上下不镜像 */
    0xDA, 0x12,  /* COM 引脚配置：128×64 用 0x12 */
    0x81, 0xCF,  /* 对比度 0xCF */
    0xD9, 0xF1,  /* 预充电周期 */
    0xDB, 0x40,  /* VCOMH 电压 */
    0xA4,        /* 显示跟随显存 */
    0xA6,        /* 正常显示（非反白） */
    0x2E,        /* 关滚动 */
    0xAF         /* 开显示 */

/* 发一条命令：0x00 是 SSD1306 的控制字节，声明后面是命令流 */
void OLED_WriteCmd(uint8_t cmd)
{
    uint8_t buf[2] = {SSD1306_CMD, cmd};
    HAL_I2C_Master_Transmit(&hi2c1, SSD1306_ADDR8, buf, 2, SSD1306_I2C_TIMEOUT);
}

/* 连续写显存数据：一个事务最多 32 字节，避免栈上开大数组 */
void OLED_WriteData(const uint8_t *data, uint16_t len)
{
    uint8_t buf[33];                    /* 1 个控制字节 + 最多 32 字节数据 */
    while (len > 0U) {
        uint16_t n = (len > 32U) ? 32U : len;
        buf[0] = SSD1306_DATA;
        memcpy(&buf[1], data, n);
        HAL_I2C_Master_Transmit(&hi2c1, SSD1306_ADDR8, buf, (uint16_t)(n + 1U),
                                SSD1306_I2C_TIMEOUT);
        data += n;
        len  -= n;
    }
}

/* 定位到第 page 页（0~7）的第 col 列（0~127） */
void OLED_SetPos(uint8_t page, uint8_t col)
{
    uint8_t cmd[4];
    cmd[0] = SSD1306_CMD;
    cmd[1] = (uint8_t)(0xB0U | (page & 0x07U));   /* 页地址命令 0xB0~0xB7 */
    cmd[2] = (uint8_t)(col & 0x0FU);              /* 列地址低 4 位 */
    cmd[3] = (uint8_t)(0x10U | (col >> 4));       /* 列地址高 4 位 */
    HAL_I2C_Master_Transmit(&hi2c1, SSD1306_ADDR8, cmd, 4, SSD1306_I2C_TIMEOUT);
}

/* 清屏：8 页 × 128 列全部写 0 */
void OLED_Clear(void)
{
    static const uint8_t zeros[SSD1306_WIDTH] = {0};
    for (uint8_t p = 0; p < SSD1306_PAGES; p++) {
        OLED_SetPos(p, 0);
        OLED_WriteData(zeros, SSD1306_WIDTH);
    }
}

/* 点亮/熄灭某页某列最上面的像素（bit0 在上） */
void OLED_Dot(uint8_t page, uint8_t col, uint8_t on)
{
    uint8_t v = on ? 0x01U : 0x00U;
    OLED_SetPos(page, col);
    OLED_WriteData(&v, 1);
}

void OLED_Init(void)
{
    for (uint16_t i = 0; i < sizeof(s_init_cmds); i++) {
        OLED_WriteCmd(s_init_cmds[i]);
    }
    OLED_Clear();
}
```

```c
        tmp[len - 1U - i] = (char)('0' + num % 10U);   /* 从最低位往前填 */
        num /= 10U;

    tmp[len] = '\0';
    OLED_ShowString(page, col, tmp);
```

::: note 这个项目里哪些代码是 CubeMX 生成的
- `MX_I2C1_Init()`（在 `i2c.c`）：I2C 模式、Clock Speed = **100000**（100kHz）、7 位地址、自身地址 0。I2C1 挂 APB1 = 36MHz，CubeMX 据此算分频。

- `MX_USART1_UART_Init()` / `retarget.c`：只用来把扫描结果打印到电脑；OLED 才是主显示。
- `SystemClock_Config()`：决定 PCLK1 = 36MHz，也决定 I2C 的实际速率；改主频后要重新核对 CubeMX 里的 100kHz。

::: note 为什么扫描用硬件 I2C、界面用轮询
- 扫描只是"试一下这个地址有没有 ACK"，`HAL_I2C_IsDeviceReady` 一次几十微秒，阻塞完全无所谓，代码最短。
- 刷新 OLED 每秒只发生一次（计数变化），轮询也不会挡住别的任务；真正需要"不卡"的场合才上 DMA/中断。
- 全程没有中断里碰 I2C：中断里做 I2C 传输一旦总线被拉死，整个系统会跟着卡住。
:::
:::

## 9. 本课小结

- I2C 两根线：**SCL 时钟 + SDA 数据**，一主多从，靠地址区分。
- 所有设备**必须开漏 + 外部上拉**；推挽会在"一个送高一个送低"时短路烧芯片。
- 起始 = SCL 高时 SDA 下降；停止 = SCL 高时 SDA 上升；数据只能在 SCL 低时变。
- 第 9 个时钟是 **ACK**（接收方拉低）；读最后一个字节主机回 **NACK**。
- 地址是 **7 位**，发送时 `addr << 1 | R/W`；0x3C 写是 0x78、读是 0x79，**别混用 7 位和 8 位**。
- 读寄存器 = 先写寄存器地址，再用**重复起始**读。
- OLED 用 SSD1306：显存 8 页 × 128 列，**一字节管一列 8 个像素**；控制字节 0x00 命令、0x40 数据。
- F103 硬件 I2C 有 BUSY 死锁勘误，学习阶段用**软件 I2C** 更稳。
- 100kHz 全屏刷 OLED 要 92ms，所以只刷变化区域。
