# 教学手册

## 课型与产出

| 课型 | 适合什么 | 课件里必须有 | 完成判据 |
| --- | --- | --- | --- |
| `concept` 概念课 | 定义、框架、辨析 | 一个具体场景 + 定义 + 三个边界/反例 + 2 道辨析题 | 能用自己的话复述并被追问不倒 |
| `practice` 实操课 | 语法、工具、题型 | 最小可运行示例 + 逐步拆解 + 3 道变式题 | 能独立改出正确结果 |
| `lab` 实验课 | 数据、实验、测量 | 步骤 + 记录表 + 一个真实小实验 | 产出可核对的数据或实验记录 |
| `project` 项目课 | 综合应用 | 目标 + 验收标准 + 拆解步骤 | 产出可运行的成品 |

## 讲法：三层下降

同一个概念，按用户反馈逐层下降，不要一上来就最抽象：

1. **场景层**：先讲一个用户能想象的具体场景（"你昨晚为什么睡不着"）。
2. **机制层**：用场景里的要素推出机制（"因为预期威胁→唤醒升高"）。
3. **形式层**：给定义、公式、术语（"这就是应激反应模型"）。

用户说"太抽象"就退回上一层；说"太简单"就补边界与反例，而不是换更难的名词。

## 出题原则

- 每题都要有**可核对**的答案（数值、代码输出、明确的判断依据）。
- 难度配比：`2 基础 : 2 变式 : 1 综合`。
- 至少一道题要求**动手**（写代码 / 算数 / 画流程）。
- 批改时指出"错在哪一步"，不只给对错。

## 评估记录模板

```markdown
# <节点标题> · 评估记录（<日期>）

| 题号 | 考查点 | 结果 | 说明 |
| --- | --- | --- | --- |
| 1 | 区分常识与实证 | 掌握 | 正确指出样本偏差 |

**结论**：掌握 / 半懂 / 未掌握
**下一步**：补前置 X / 重讲 Y 的机制层 / 进入下一节点
```

## 记忆规则

`memory/profile.md` 只记稳定的东西：现有水平、可投入时间、学习目标、已学过的科目。每次评估后更新一次，不要每天重写。

`memory/preferences.md` 记"怎么讲有效"，一行一条，例如：

```
- 心理学：先给生活场景再给术语，有效
- 统计：先给具体数字算一遍，再上符号，有效
- 一次讲超过 3 个新术语会卡住，需要拆课
```

新增条目要能让下一次会话直接照做，不要写"注意因材施教"这种无法执行的废话。

## 会话开场

新会话先读 `memory/profile.md` 与当前科目的 `course.json`，用两行汇报：学到哪、下一步是什么。然后直接进入内容，不要重新做入学评估。
