# Study Mate · 学习搭档

一套"学了就留下痕迹"的自学系统。原则：**learn with doing** —— 每个知识点都要有可检验的产出，不是把教材念一遍。

## 一、先定位两个路径

1. **插件根**：本文件在 `<插件根>/skills/study-mate/SKILL.md`，往上两级就是插件根。
2. **学习工作区**（所有课件与记忆都在这里，不要散落在别处）：
   - 项目根目录下已有 `StudyMate/` → 用它；
   - 否则用 `%USERPROFILE%\StudyMate`（即 `~/StudyMate`）。
   - 用户显式指定时以用户为准。

工作区目录结构与文件格式见 `references/workspace-schema.md`；课型、讲法、练习设计与记忆规则见 `references/teaching-playbook.md`。**动笔前先读这两份。**

## 二、四种典型意图

### A. 开新科目（"我想学 C++ / 教我统计学 / 帮我入门嵌入式"）

1. 先做**入学评估**：最多问 4 个问题（目的、现有基础、每周可投入时间、想怎么检验学会了）。用户已经说清楚的就不要再问。
2. 建目录：`StudyMate/subjects/<subject-id>/lessons/`、`notes/`、`records/`。
3. 写 `course.json`：知识点按**前置依赖分层**（layer 从 1 开始），每个节点标课型 `concept | practice | lab | project`，并写 `summary`（一句话说清这个知识点要能做什么）。
4. 写 `workspace.json`，把新科目登记进去（已存在则追加 `subjects` 数组）。
5. 把评估结论写进 `StudyMate/memory/profile.md`（水平、时间、目标）与 `preferences.md`（讲法偏好）。
6. 向用户展示路线图（文字版：分层 + 节点数 + 建议第一课），并**直接写第一课的课件**，不要只给大纲就停。

### B. 继续学习（"继续 / 下一课 / 讲到第 N 个知识点"）

1. 读 `course.json`，找到第一个 `todo` 或 `in_progress` 节点（前置节点必须已 `done`）。
2. 按该节点课型写课件到 `lessons/<序号>-<slug>.md`，并把 `course.json` 里对应节点补上 `lesson` 字段、状态改 `in_progress`。
3. 一篇课件只讲**一个**知识点，默认 30–50 分钟能读完 + 做完练习。

### C. 答疑（"这里没懂 / 太抽象了 / 换个讲法"）

1. 当场只解释卡住的那一小段（不超过 300 字），给一个具体例子。
2. 判断是**讲法问题**还是**前置知识缺口**；后者就在 `course.json` 里补一个前置节点。
3. 把这条卡点写进 `StudyMate/memory/preferences.md`（"对 X 用类比讲有效" / "不要先给公式"）。

### D. 检查与评估（"考考我 / 我学得怎么样"）

1. 针对**当前节点**出 3–5 题：概念辨析、给场景判断、动手写/算。题目要能写出可核对的标准答案。
2. 用户答完后逐题批改，写一份 `records/<节点>-<日期>.md`：掌握 / 半懂 / 未掌握 + 下一步建议。
3. 按结果更新 `course.json` 的节点 `status`，并在 `progress.json` 追加一条记录。

## 三、课件写作规范（重要）

课件是学习的主载体，用 Markdown 写，允许自定义**提示块**（阅读端会渲染成卡片）：

```markdown
---
node: p1
title: 心理学研究什么
type: concept
duration: 40
---

## 这一课要解决的问题

::: goal
读完你能：区分常识与心理学结论；说出科学方法的四步。
:::

::: key
**核心定义**：心理学是研究行为与心理过程的科学。
:::

::: example 例子：从"直觉"到"数据"
...
:::

::: warn
常见误解：弗洛伊德 = 心理学全部。实际上……
:::

::: exercise 练习 1
题干（可含公式，$E[X]=\sum x_ip_i$）

::: answer
参考答案（默认折叠）
:::
:::

::: project 项目
做一件具体的事，附验收标准。
:::

::: selfcheck 自检
- [ ] 我能用自己的话解释……
:::
```

硬性要求：

- 每个 `##` 小节解决一个问题，标题写成"问题"而不是"名词"。
- 抽象概念先给**具体场景**，再给定义，最后给边界（什么情况不适用）。
- 公式必须配一个带数字的例子，并说明每个符号的含义。
- 练习必须有可核对的答案，不要出"谈谈你的理解"这类无法判分的题。
- 需要图时优先用内联 `<svg>`（离线可看）；不用外部随机图片。
- 不写"综上所述""让我们一起"这类空话；直接讲内容。

## 四、启动阅读端

如果用户装过带活动栏图标的扩展（左侧「学习搭档」），直接提示点图标即可，不必再启动服务。

否则，用户想"看课件 / 打开学习界面"时，在项目根执行（PowerShell）：

```powershell
node "study-mate/app/server.mjs" --workspace "StudyMate" --open
```

- 默认端口 4310，被占用会自动顺延；终端会打印真实地址，把地址告诉用户。
- 插件被安装到别处时，把上面路径换成 `<插件根>/app/server.mjs`，工作区用绝对路径。
- 只想验证不打开浏览器时加 `--no-open`。
- 用户说"课件打不开/页面空白"时，先跑 `--no-open` 看终端报错，并检查 `course.json` 是否为合法 JSON。

## 五、更新数据的两种方式

- **阅读端里点"标记完成"**：前端会 `POST /api/status`，服务端直接改 `course.json`，你不需要再动手。
- **对话里改**：用 Edit 改 `course.json` 的 `status`，并往 `progress.json` 追加一条 `{ "at": "ISO时间", "subject": "...", "node": "...", "status": "done" }`。

两边都不要改别的字段；`progress.json` 只追加，不重写历史。

## 六、不要做的事

- 不要把所有科目塞进一个巨型 `course.json`；一科一目录。
- 不要预生成一堆没讲过的课件充数；讲一课写一课。
- 不要在课件里写"详见上文/详见教材"——课件本身要能独立读懂。
- 不要每次开新会话就重新问一遍基础信息；先读 `memory/`。
